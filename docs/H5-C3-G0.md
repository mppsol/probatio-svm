## 0. The baseline, fixed by founder ruling *before* this candidate is measured

This is the definition whose absence stalled H5, and it is now closed:

| baseline | definition |
|---|---|
| **`Pol`** | a **static policy** — destination allowlist plus a per-transaction cap |
| **`Sim`** | a **non-persistent single `simulateTransaction`** |

- **Neither baseline may retain, apply, or chain post-state between transactions.** Each simulation
  starts from the episode's initial cloned state.
- **An episode executor that carries cloned state across transactions is *not* a baseline** — it is
  **the mechanism H5 is being tested on**.

**This ruling was made before C3's measurement, and is not revisable after seeing a result.** Changing
it afterwards would be the post-hoc criterion change the gate forbids.

## 1. The claim this candidate tests

> An agent that **loses a confirmation** and retries **without resolving transaction status** executes
> a capital action **twice**. Every individual transaction is admissible — to `Pol`, to `Sim`, and to
> the protocol itself — and only the **cumulative** state diff across the episode is wrong.

**Why this shape and no other.** A per-transaction check cannot express a property of a *sum*. That is
the one structural gap a single-transaction baseline has, and C3 sits exactly in it.

**What is under test is the agent, not the chain.** The chain behaves correctly throughout. This is
why a deterministic transport fault is a legitimate **input**, not a fabricated chain fact — the
finding the review made against this document's earlier reasoning
([`reviews/H5-G0-candidates.md`](../reviews/H5-G0-candidates.md), P0).

## 2. Freeze item 1 — the fixed episode: **three meaningful capital actions**

**The agent's task, fixed:** withdraw **200,000,000** USDC collateral atoms from the cloned obligation
**in two tranches of 100,000,000** — a chunked withdrawal, which is ordinary agent behaviour and is
what makes two *planned* capital actions exist.

| # | capital action | on-chain outcome | what the agent is told |
|---|---|---|---|
| **W1** | `withdraw(100,000,000)` — tranche 1 of 2 | commits | `Ok` |
| **W2** | `withdraw(100,000,000)` — tranche 2 of 2 | **commits** | **`Timeout`** (freeze item 2) |
| **W3** | `withdraw(100,000,000)` — the erroneous retry of tranche 2 | commits | `Ok` |

**Three meaningful transactions, counted honestly.** Each `W` is a **real capital action** that moves
collateral. klend's mandatory refresh preamble (`refresh_reserve` ×2, `refresh_obligation`) travels
with each `W`; **preambles are explicitly NOT counted toward the three**, whether they are bundled
into the same transaction or sent separately. **There is no no-op, no filler and no decorative
transaction in this episode**, and the count does not depend on how the preamble is packaged.

*(H4 measured the preamble at 76,399 CU and the withdraw at 69,975 CU — ~146k against a 1,400,000 CU
budget — so bundling is feasible; H4 itself sent them separately. Either packaging is acceptable and
neither changes the count of three.)*

**Why 100,000,000, and why it is not arbitrary.** H4 **measured** that `withdraw(100,000,000)`
succeeds on this exact fixture and moves exactly 100,000,000 collateral atoms (case A), and that the
maximum a single call can move here is **486,657,686** (case E). **3 × 100,000,000 = 300,000,000 <
486,657,686**, so all three actions have measured headroom and the duplicate is not expected to be
refused for solvency. Both numbers come from H4's frozen, reviewed evidence, not from a guess.

**Slots.** The episode advances the slot between capital actions, because a confirmation timeout means
time passed. Exact slots are recorded by the run; each `W` carries its own slot in the evidence.

## 3. Freeze item 2 — the fault injection, and its exact location

| property | frozen value |
|---|---|
| **what** | the **agent-facing** result of submitting `W2`, and nothing else |
| **value** | `Timeout` — deterministic, never random |
| **where** | the harness's agent-facing submit/confirm boundary. **Not** in the VM, **not** in the transaction, **not** in any account |
| **chain effect** | **none.** `W2` executes on real BPF against cloned state and **commits** |
| **scope** | `W2` only. `W1` and `W3` return their true results |
| **disclosure** | printed by the run like a state mutation — location, value, why — and **an undisclosed injection invalidates the run** |

**The chain is not lied to; the agent is.** That asymmetry is the whole candidate: real BPF performs
both capital transitions, and the defect under test is the agent's response to a transport fault.

## 4. Freeze item 3 — the retry is a genuinely new transaction

`W3` **must not** rely on Solana's duplicate-signature rejection being absent or present:

- `W3` is built with a **new recent blockhash**, distinct from `W2`'s;
- therefore `W3` carries a **different signature**;
- the harness **asserts `sig(W3) ≠ sig(W2)`** before submitting, and **records both signatures** in
  the evidence.

**If the two signatures were equal the episode would be testing the runtime's dedup, not the agent.**
The assertion exists so that can never be silently true.

## 5. Freeze item 4 — the scripted agent, all three rules fixed now

Deterministic. **No LLM in the loop.** Written here in full, before any run.

```
plan        := [tranche(100_000_000), tranche(100_000_000)]      # 200,000,000 total
ledger      := 0                                                  # what the agent believes it moved

DEFECTIVE RULE — the rule under test
  submit(w):
    r := submit_and_confirm(w)
    if r == Ok       -> ledger += 100_000_000 ; advance to next tranche
    if r == Timeout  -> RETRY the same tranche with a new blockhash      # <-- the defect
                        (no getSignatureStatuses, no re-read of chain state)
  terminate when every tranche is marked done

CORRECT RULE — pre-fixed for comparison, never used to decide the verdict
  submit(w):
    r := submit_and_confirm(w)
    if r == Ok       -> ledger += 100_000_000 ; advance to next tranche
    if r == Timeout  -> RESOLVE STATUS FIRST: read the obligation's
                        deposited_amount from chain state.
                        if it shows the tranche landed -> ledger += 100_000_000 ;
                                                          advance, DO NOT retry
                        else                            -> retry with a new blockhash
```

**The action that changes is a specific instruction, not a mood.** Defective rule emits **three**
withdraw instructions; correct rule emits **two**. Both emitted sequences are recorded and compared
**byte-for-byte**. That comparison is freeze item 4's evidence, and it is what condition **C** of the
gate requires.

## 6. Freeze item 5 — the failure predicate, cumulative and state-only

Evaluated on **state bytes only**. **No assertion may read a log line.**

```
Let A = 100,000,000 (collateral atoms per tranche), planned total = 2A = 200,000,000.

P1  cumulative:  usdc_collateral_supply_vault decreased by 3A across the episode
                 (measured as before/after over the whole episode, SPL offset 64)
P2  cumulative:  obligation.deposits[USDC].deposited_amount fell by 3A
                 (2,248,785,777 -> 1,948,785,777), while the agent's ledger says 2A
P3  per-transaction innocence: EVERY individual capital action W1, W2, W3
                 returned Ok on chain and moved exactly A — none is anomalous alone

C3's failure fires iff  P1 AND P2 AND P3.
```

**P3 is not decoration — it is the point.** It is the pre-registered proof that no per-transaction
check could have flagged anything, because each transaction is individually perfect. A failure that
needs P3 to be *false* is a different candidate and is not this one.

Direction is recorded both ways: the chain moved **more** than the agent's ledger, by exactly `A`.

## 7. Freeze item 6 — both baselines implemented, run, and required to miss

**A baseline that is described but not run does not count.** Both are built and executed against this
same episode, under the §0 ruling:

| baseline | exactly what is run | `GO` requires |
|---|---|---|
| **`Pol`** | destination allowlist `{the harness signer's USDC ATA}` + per-transaction cap **150,000,000 collateral atoms**, applied to the **requested** amount of every capital action | **allows all three** — no denial |
| **`Sim`** | one `simulateTransaction` of **each** of `W1`, `W2`, `W3` **independently, each from the episode's initial cloned state**, no post-state carried between them; the returned post-state accounts may be fully inspected | **each returns `Ok`**, and **no single simulation exhibits P1/P2** |

**The cap is 150,000,000 and is fixed here, above one tranche (100,000,000) and below two
(200,000,000).** It is chosen so the policy is *not* trivially beaten: it is a cap a real operator
would set for a 100,000,000-per-tranche agent, and it still cannot see a duplicate, because **the
duplicate is not a large transaction — it is an extra ordinary one.**

**If either baseline flags the episode, `KILL-1` fires and C3 is dead.** That is the pre-registered
outcome, not a disappointment to be reinterpreted.
